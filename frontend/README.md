# WeakAppHandler Frontend

React 19 + TypeScript + Vite, talking to the Gateway's GraphQL API via Apollo Client.

## Scripts

- `npm run dev` — start the Vite dev server.
- `npm run build` — type-check (`tsc -b`) and produce a production build. Runs `codegen` first
  (via `prebuild`), so it always builds against fresh generated types.
- `npm run codegen` — regenerate `src/gql/` from the Gateway's committed
  `../src/Gateway/WeakAppHandler.Gateway.Api/schema.graphql` and every `.graphql`/gql-tagged
  document under `src/`. Run this after adding or editing a query/mutation, and after the Gateway's
  schema snapshot changes.
- `npm run lint` — ESLint over `src/`.

## Structure

Feature-sliced:

- `app/` — app shell, providers, routing root.
- `features/` — user-facing feature slices (one directory per feature).
- `entities/` — domain read models shared across features (e.g. a meter, an alert).
- `shared/` — cross-cutting UI/utilities with no feature-specific meaning.
- `gql/` — generated by `npm run codegen`; never hand-edited, not committed (see `.gitignore`) and
  excluded from both ESLint and the TypeScript project's own root file set.

## GraphQL codegen

`codegen.ts` points at the Gateway's own `schema.graphql` snapshot rather than live introspection,
so codegen works with no backend running. It uses the `client-preset`, so components use Apollo's
`useQuery`/`useMutation` directly against a `graphql()`-tagged, fully-typed `TypedDocumentNode` —
there are no separate generated hook functions to keep in sync.
